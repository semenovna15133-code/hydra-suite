# ПРИЛОЖЕНИЕ v5.1 (29.10.2026) — клиентский цикл 0.7.0–0.7.7

Фиксирует решения и факты, добытые боевыми тестами на реальном устройстве
(Samsung SM-G975F, Android 12) 27–28.10.2026. Не переписывает тело манифеста,
дополняет его. При слиянии с основными разделами приоритет у этого приложения
по клиентской части до момента слияния.

## A.1 Новые ADR

- **R-24 sessionExplicit — источник правды о режиме сессии.** Флаг
  `HydraVpnService.sessionExplicit` выставляется ровно в двух воронках:
  `connectExplicit()` = true (явный тап на голову протокола),
  `autoConnectInner()` = false (центральная кнопка AUTO). Все guard'ы
  (failover, onWdttDead, onNetworkChanged, uiMessage) читают его.
  Статический `MainActivity.explicitProtocol` остаётся только для UI-подписи
  режима. Урок 0.7.5: несвежий статический флаг ложно блокировал failover
  в AUTO-сессии («WDTT dead in explicit mode» при живом AUTO).
- **R-25 WakeLock + battery exemption как условие жизни туннеля.**
  PARTIAL_WAKE_LOCK (refCounted=false, cap 24ч) на время активного туннеля +
  разовый диалог `ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` через 2.5с
  после старта activity (раньше — startActivity молча падал). Причина:
  Doze замораживал wdtt-client, keepalive не уходили, VK TURN закрывал
  сессии через 10–14с после гашения экрана. После применения: session age
  вырос с 45–49с до 240+с, массовые смерти воркеров исчезли.
- **R-26 Экспорт логов в Загрузки через MediaStore.Downloads.** Без runtime-
  permission (API 29+), тост «Лог сохранён: Загрузки/…», системный шаринг
  только как fallback. Конец кругообороту логов через мессенджеры.
- **R-27 evidence = трафик, а не handshake (уточнение R-20).** Живость
  туннеля доказывается дельтой rx/tx (tun-статистика для AWG, hb_stats.json
  для bridge-протоколов). Handshake-флаги Go могут врать в обе стороны;
  UID-счётчики TrafficStats считать нельзя (считают весь UID, включая
  соседние процессы — источник ложных подтверждений и «багажа»).
- **R-28 preferred-first.** Явный выбор протокола (тап на голову или
  preferred в настройках) идёт ПЕРВЫМ кандидатом и не уничтожается
  пересортировкой по score. Урок 0.7.4: «Preferred protocol: WDTT, trying
  first» в логе при фактическом запуске AWG из-за повторной сортировки.
- **R-29 Контракт смерти кандидата в AUTO.** Смерть протокола = штраф
  (ProtocolMemory) + failover на другой протокол; протокол возвращается
  в ротацию после остывания штрафа. In-place restart того же протокола
  в AUTO ЗАПРЕЩЁН (гонка двух транспортов за один TUN и порты, порча
  штрафов). Restart допустим только в explicit-сессии ограниченными
  ретраями с последующим честным диалогом.

| 0.7.1 | explicit-режим через провайдеров (фикс пустых peer-данных) |
| 0.7.2 | whiteList-aware failover; sendTunFd retry 5→10 (backoff 500–5000мс); zombie-детект AIVPN с проверкой hb_stats |
| 0.7.3 | WakeLock; SCREEN_ON receiver (мгновенная проверка после пробуждения); battery exemption; WAKE_LOCK permission |
| 0.7.4 | preferred-first; supervised retries не перехватывают explicit; свежая EnvironmentProbe-проба при смене сети; explicit-реконнект того же протокола |
| 0.7.5 | wdttSessionStartMs + session age при «tcp active closed»; REQUEST_IGNORE_BATTERY_OPTIMIZATIONS permission; точные исключения в логе батареи |
| 0.7.6 | sessionExplicit (R-24) — конец ложным блокировкам failover |
| 0.7.7 | экспорт логов в Загрузки (R-26) |

Итоговое поведение: explicit-тап = контракт «этот протокол или честная
ошибка»; AUTO = скоринг + probe + failover; смена сети = свежая проба +
whiteList-бонус WDTT (+50); сон экрана не убивает туннелю сессии.

## A.3 Известные проблемы и лимиты

- **VK TURN закрывает idle-сессии (~45–60с без keepalive).** На клиенте
  компенсировано R-25 (WakeLock держит CPU, keepalive идут). Серверная
  часть в бэклоге: тюнинг keepalive-интервала wdtt-client / ротация хешей.
- **legacy `restartTunnel ignored: … (not AWG)`** — мёртвый код эпохи
  AWG-only в ReconnectManager; к удалению при следующей чистке.
- **AIVPN TMPDIR:** /tmp закрыт SELinux для untrusted_app; решение —
  cacheDir + symlink без su (su отсутствует на большинстве устройств).
- **Samsung app sleep** может переживать battery exemption на отдельных
  прошивках — наблюдать по логам (маркер: тишина периодических [hb]-строк
  при живом сервисе).
- **Размер APK ~30 МБ (arm64)** — три ядра (Go×2 + нативный AWG); приём
  «лёгкого» билда с одним протоколом отложен сознательно.

## A.4 Диагностика (инструментарий клиента)

- DevLog-теги: `WDTT-watchdog` (active/zeroSince/notified), `WDTT-DEATH`
  (сырые строки FAILED/PAUSED/«осталось:»), `HydraUI` (батарея, режимы).
- `tcp active closed: session age = Ns (alive workers: M)` — возраст
  сессии на момент закрытия; различает Doze (10–14с), TURN-idle (45–60с),
  серверную ротацию (произвольный N).
- hb_stats.json (rx/tx/session_ms/dup/retrans) — evidence и здоровье
  bridge-сессии; читается UI, HealthMonitor, zombie-детектом.
- Zombie-детект AIVPN: ≥3 «handshakes never connected» подряд → штраф,
  НО только если hb_stats не показывает трафик (иначе — ложная тревога).

# ПРИЛОЖЕНИЕ A.7 (29.10.2026) — WDTT на cellular: NAT timeout и план решения

## A.7.1 Критическое открытие (уточнение от 29.10.2026)

**Первоначальная гипотеза (опровергнута):** "WDTT на cellular умирает через 60с" — наблюдалось в логах 19:47, 23:39, 23:52, но оказалось **не универсальным**.

**Актуальное понимание:** WDTT на cellular может жить как 60 секунд, так и 7+ минут — зависит от конкретной сети (базовая станция, оператор, время суток, нагрузка). Примеры:
- ❌ 19:47 (28.10): смерть через 45-60с, 27 воркеров падают одновременно
- ✅ 17:38 (29.10): стабильная работа 7+ минут, 27 воркеров живы, 400+ МБ трафика, 0 failover

**Реальный корень:** не NAT timeout как таковой, а **нестабильность конкретных TURN-аллокаций VK** на определённых сетях. Keepalive работает (много `[HEALTH] сервер ответил на keepalive`), но некоторые аллокации умирают, а некоторые живут долго.

**Корень:** наш wdtt-client идёт через **TURN TCP** (`[CONNECTION] TRY tcp`, `[СЕССИЯ #N] Relay: ... через TURN TCP`). TCP-аллокации на мобильных сетях живут меньше; клиент не перебирает транспорты.

**Почему WDTT Plus работает на той же сети и том же сервере** (анализ репозитория Ivan4537/WDTT-Plus, go_client):
- **keepaliveInterval = 15s** (DTLS keepalive), keepalivePongTimeout = 75s
- **unansweredUserTrafficTimeout = 45s** — рестарт воркера если трафик без ответа
- **Мульти-транспорт:** перебор TURN UDP / TCP / TLS (`turn_endpoint.go`), для белых списков — TLS-first с белым SNI (`turns:`)
- **Wake-probe при Doze:** DEVICE_SLEEP/WAKE команды, `workerWakeProbeTimeout = 12s`, per-worker проверка после пробуждения
- **Замена канала:** 2+ failed delivery probes → замена одного воркера, не всей сессии
- **WRAP RTP AEAD** поверх DTLS (маскировка под медиатрафик) — у нас тоже есть

## A.7.2 Временное решение (0.7.11, клиентское)

Health monitor в SmartConnectManager: дельта rx каждые 10с; нет прироста 75с → failover. Компенсирует, но не лечит (переподнятие каждые ~60с).

## A.7.3 Постоянное решение

**Вариант A (приоритет 1):** убрать `-turn-stream-first` из запуска wdtt-client → клиент начнёт пробовать TURN UDP первым (как апстрим по умолчанию).
**Вариант B (приоритет 2):** форк/сборка нашего wdtt-client с параметрами апстрима: keepalive 15s, unanswered-traffic 45s, wake-probe, мульти-транспорт (по образцу go_client WDTT Plus).
**Вариант C:** TURN TLS с белым SNI для самых жёстких сетей (как у апстрима).

## A.7.4 Таблица отличий

| Параметр | Наш клиент | апстрим (форк) |
|---|---|---|
| TURN транспорт | только TCP | UDP / TCP / TLS перебор |
| Keepalive | есть (сервер отвечает) | 15s + pong timeout 75s |
| Unanswered traffic restart | нет | 45s |
| Wake-probe при Doze | нет | 12s, per-worker |
| Замена мёртвого воркера | нет | 2+ failed probes |
| Сессия на cellular | 60с — 7+ мин (нестабильно) | стабильно |
